## Verification-history lessons

Historical verification defects fell into four classes:

1. a filtered command selected no tests but exited successfully;
2. a status artifact was written without the claimed product journey running;
3. test doubles proved only another test double or a declaration/source string;
4. browser or platform coverage visited only part of the surface it claimed.

The durable rule is direct product evidence: verification must execute the
production caller and the behavior it names. Empty filters, source-text
presence, module layout, declaration agreement, and unvisited UI routes cannot
establish acceptance. This is a lesson, not a new gate or prescribed test list.

Historical deleted-test review also established:

- a deleted test path is not necessarily deleted coverage; locate migrated
  assertions before filing a gap;
- absence of an in-file test module does not prove absence of production-path
  coverage;
- restoration must target retained behavior, not revive obsolete test or
  module structure; and
- direct generation rebuild after reopen remained genuine residual debt.
