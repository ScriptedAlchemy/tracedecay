# Workflow V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the retained host-neutral Plan 24/32 Workflow product through one daemon-owned, event-journaled runtime with real DAG dataflow, pinned authorities, explicit placement/effects, provider-neutral configuration, atomic combined automation, and common application surfaces.

**Architecture:** Extend the existing `WorkflowSqliteAuthority` and canonical Work runtime instead of adding a parallel scheduler or database. Immutable workflow definitions and run events retain exact scopes, snapshots, typed output/artifact references, leases, effects, and terminal evidence; adapters call one application service. Existing persisted workflow rows are read only to report `MigrationRequired` until `tracedecay migrate` performs the explicit cutover.

**Tech Stack:** Rust 2024, rusqlite migration-SQL authority, petgraph, Tokio/tokio-util, schemars/Serde, existing Work provider/runtime/catalog/configuration/application bindings.

## Global Constraints

- Work only in `/fast/projects/tracedecay/.worktrees/v2-workflow-host-neutral` on `codex/v2-workflow-host-neutral`.
- Do not merge/rebase main, touch remote modules, host lifecycle, generic application-surface metadata, dashboard/SDK generator catalogs, or auto-run schema/data migration.
- Tests precede production changes and must be observed failing for the intended missing behavior.
- Commit each coherent slice with a conventional commit subject.
- Preserve existing data through explicit migration only; runtime returns typed `MigrationRequired`.
