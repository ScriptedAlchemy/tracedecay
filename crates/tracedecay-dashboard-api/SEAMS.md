# `tracedecay-dashboard-api` split seams

Mover output for the one-shot crate split
(`docs/superpowers/plans/2026-07-31-one-shot-crate-split.md`), updated after
the repointing pass.

`src/dashboard/` (26 457 lines, 43 files) moved here. `src/dashboard/assets.rs`
stayed in the root crate because its bundle is generated by the root `build.rs`
into `OUT_DIR` and included with `env!("OUT_DIR")`, which only resolves inside
the crate that ran that build script. `src/dashboard.rs` is now a shim:
`pub(crate) use tracedecay_dashboard_api::*;` plus `pub(crate) mod assets;`.

## Status

`cargo check -p tracedecay-dashboard-api --all-features` → **169 errors**
(145 × E0433, 24 × E0432). `--no-default-features` → 168. Every one is still an
unresolved *path*; there are zero type errors, so the catalog below is
exhaustive.

Trajectory this pass: **211 → 169**, but the two numbers are not directly
comparable — see "Hidden references surfaced" below. Like-for-like the crate
went from 211 to 169 while also exposing 9 references the compiler had been
silently swallowing, so 51 real references were resolved.

The residual splits cleanly in two, and **neither half is fixable from inside
this crate**:

| Class | Errors | Blocked on |
|---|---:|---|
| Extracted crates that do not compile yet | 75 | the agent-hosts, sessions and global-db movers |
| Root modules with no extracted destination | 94 | root-side extraction or the inversions designed below |

`cargo fmt -p tracedecay-dashboard-api --check` is clean.

## Blocker: three destination crates do not compile

The paths in this crate are already repointed at their final destinations, but
the `[dependencies]` entries are **deliberately held back**, because those
crates fail to build standalone:

| Crate | Own errors | Why |
|---|---:|---|
| `tracedecay-agent-hosts` | 194 | its own unrepointed `crate::{errors,db,application,mcp,serve,accounting}` seams |
| `tracedecay-sessions` | 220 | same class, plus one `E0223` |
| `tracedecay-global-db` | 279 | transitively via `tracedecay-migrate`, which does not compile |

Adding the dependencies today would make `cargo check -p
tracedecay-dashboard-api` fail with ~700 errors sourced from *other* crates,
destroying the ability to measure this crate at all. Keeping them out costs
nothing: the source paths are final either way, and the errors stay one per
reference.

**Once those three crates build, this is the whole remaining step** — add to
`[dependencies]`:

```toml
tracedecay-agent-hosts = { path = "../tracedecay-agent-hosts", version = "0.1.0" }
tracedecay-global-db   = { path = "../tracedecay-global-db",   version = "0.1.0" }
tracedecay-sessions    = { path = "../tracedecay-sessions",    version = "0.1.0" }
```

and to `[features]` (this crate's `#[cfg(feature = …)]` blocks mirror the
root's, and the root already forwards both):

```toml
token-counting = ["dep:tiktoken-rs", "tracedecay-agent-hosts/token-counting"]
test-transport = ["tracedecay-agent-hosts/test-transport"]
```

That clears 75 of the 169 errors with no source change. Acyclicity was checked
with `cargo metadata`: none of the three depends on `tracedecay-dashboard-api`,
directly or transitively.

## Resolved this pass

### Kernel paths → `tracedecay-runtime-core`

`crate::{branch, db, errors, lifecycle_lease, memory, storage, store,
timeutil, worktree}` and `crate::tracedecay::current_timestamp` now name
`tracedecay_runtime_core::…`. The kernel crate compiles standalone, so this
slice is verified rather than assumed.

Two same-name traps were checked by hand rather than trusted:

- **`branch`** — the root's `src/branch.rs` is *not* a shim (it keeps the
  branch-admin surface). The kernel owns a deliberate slice containing
  `current_branch`, which is the only item this crate uses. Correct as
  repointed.
- **`project_registry`** — the root and kernel modules are unrelated. The
  kernel owns `primary_checkout_root`; `ProjectRegistrySummary`,
  `ProjectRepoGroup`, `PublicCodeProject` and `build_project_registry_view`
  are root-owned types built over `global_db`. A blanket repoint mis-targeted
  all four (surfacing as `E0425`); they are back on `crate::project_registry`
  and listed as a seam below.

`db`, `errors`, `memory`, `storage`, `timeutil`, `worktree` and
`lifecycle_lease` were each confirmed to be root shims over the kernel, and
`store::memory` a kernel-owned slice.

### Embedded assets — resolved with option (a)

Per the lead's ruling, `router()`, `run()`, `run_until_shutdown()`,
`run_until_shutdown_for_tests()` and
`run_until_shutdown_for_tests_with_host_admission()` take a new
`spa_routes: axum::Router` parameter (positioned before `shutdown`, so the
closure stays last), threaded through `run_until_shutdown_inner()` and
`router_with_active_application()`.

It is merged **after** `.with_state(runtime)`, so:

- `spa_routes` is a stateless `Router` (`Router<()>`);
- it owns the app index, `/static/{*tail}` and the SPA fallback — this crate no
  longer calls `.fallback(…)`, and `Router::merge` panics if both sides set
  one;
- it must not define any `/api/**` route, which would collide;
- `Router::new()` is a valid argument, serving the JSON API with no UI.

The three `// SEAM(assets)` markers are gone. **Root wiring:** the root builds
this router from `src/dashboard/assets.rs` and passes it at every call site of
the five entry points.

### `PinnedUserDataDir` — inverted into this crate

Verified against the ruling's conditional: `PinnedUserDataDir` did **not** move
with the kernel config module. It is still in the root's `src/config.rs` behind
`#[cfg(test)]`, so it is unreachable across the crate boundary. It is now
defined in `src/test_support.rs` over the kernel's `TRACEDECAY_DIR`,
`USER_DATA_DIR_ENV` and `PrivateStoreIo`, covering all 33 test references.

This is also a correctness fix, not just a repoint: the guard serializes on a
`static` mutex, and a `static` is per-test-binary, so the root's lock never
serialized this crate's tests. The root should keep its own copy.

### Hidden references surfaced

`src/lib.rs` had `use …automation::config::{self, …}` at the **crate root**.
That binding shadowed `crate::config`, so nine real `crate::config::…`
references resolved against the automation config module instead of erroring —
and `tracedecay_automation::config` happens to define its own
`RetentionConfig`, so the shadow was live, not theoretical. The import is now
`{self as automation_config, …}` and the nine references are visible as errors.

The pre-existing count of 211 was therefore understated; the honest baseline
was 220.

### Sessions test module

`src/lib.rs` kept `#[cfg(test)] #[path = "../../../src/sessions/lcm/
dashboard_fixes_tests.rs"]`, which no longer exists — the sessions mover
relocated the file to `crates/tracedecay-sessions/src/runtime/lcm/`, where
nothing declares it. It is a *dashboard* test (`super::*` resolves to this
crate's root and it drives an `axum::Router` over `DashboardState`). The
`#[path]` now follows the file so the coverage is not dropped and `cargo fmt`
resolves again. **Root wiring:** physically move the file back under this crate
(`src/` or `tests/`) and delete the attribute.

### MCP coupling — inverted (from the previous pass)

`crate::mcp::server::RetainedProjectGraph{Request,Future,Resolver}` now lives in
[`src/project_graph.rs`], and `src/mcp/server.rs` re-exports it. This crate has
zero code references to `crate::mcp`.

### `crate::types`

A pure façade over `tracedecay-domain` / `tracedecay-application`; its three
references import `tracedecay_domain::code_intelligence::{Edge, Node,
FileRecord, GraphStats}` directly.

### Visibility

All 491 `pub(crate)` items in the moved files became `pub`; the root shim's
`pub(crate) use …::*` restores the original visibility, so no root or
integration-test import changed. **No visibility widening outside this crate
was needed in this pass.**

### The two structural ones

**`crate::tracedecay` (16).** Splits into three unrelated problems:

- `facts::memory_application_for_db` — 11 refs. A four-line constructor over
  `MemoryApplication` + `DatabaseFactStore`. `DatabaseFactStore` is already in
  the kernel, so this is a candidate to define here directly.
- `TraceDecay` — 7 refs, but it is load-bearing: it is the `cg` parameter of
  `router`, `run`, `run_until_shutdown*` and `build_state`, and the element
  type of `DashboardState::project_graph`. The struct is root-only
  (`src/tracedecay.rs`); the kernel's `tracedecay` module contains only
  `current_timestamp`.
- `TraceDecayOpenOptions` (4, test-only) and `is_test_file` (1).

  Inversion design: this crate needs exactly **15 methods** —
  `store_layout`, `project_root`, `dashboard_db_path`, `storage_telemetry_handle`,
  `get_config`, `configuration_runtime`, `profile_database`,
  `dashboard_database_guard`, `db`, `get_node`, `get_stats`, `get_callers`,
  `get_call_chain`, `get_test_annotated_node_ids`, `last_synced_commit`. Their
  return types are mostly already reachable (`StoreLayout`, `Database`,
  `RegisteredGlobalDb`, `Node`/`Edge`/`GraphStats`), so a
  `trait DashboardProjectGraphV1` here with the root implementing it for
  `TraceDecay` is viable. Two returns leak root types and must be inverted with
  it: `get_config() -> TraceDecayConfig` (see `config` below) and
  `configuration_runtime()`. Six of the fifteen are `async`, so the trait needs
  boxed futures to stay `dyn`-safe.

**`crate::application` (37).** Root `src/application/` is real root-owned code,
not a shim over `tracedecay-application`; only `MemoryApplication` has a crate
equivalent. By submodule: `observability` 11, `host_admission` 9 (test-only),
`event_lane` 6, `dashboard_diagnostics` 6, `memory` 5, `feedback` 4, `context`
3, `configuration` 3, and one each of `settings_control`, `operation_stream`,
`git_reads`, `doctor_remediation`.

  Recommended split rather than one sweep:
  - `host_admission` (9) is entirely `#[cfg(test)]` — it moves with whichever
    crate owns the test harness, and costs nothing until tests compile.
  - `observability` (11) is a *composition* layer over `tracedecay-application`
    plus `global_db`, both of which this crate can reach. It is the best
    candidate to move here outright once `global-db` builds.
  - `event_lane`, `dashboard_diagnostics`, `configuration::UserSettingsDaemonClient`,
    `doctor_remediation` and `operation_stream` are injected authorities →
    port traits on `DashboardState`, alongside the existing
    `project_graph_resolver` field.
  - `context`, `git_reads`, `feedback::observations` and `memory` are value
    types and pure reads → move or re-export.

### `crate::config` (9 production)

Now visible after the shadowing fix. Three separable pieces:

- `RetentionConfig` — 6 refs, but this crate calls exactly **one** method,
  `store_soft_budget(&str) -> Result<Option<StoreSizeBudgetV1>>`. A
  `trait StoreSoftBudgetPolicyV1` here, with `DashboardState::retention_config`
  becoming `Arc<dyn …>`, is a clean and very small inversion. (Note the root's
  `store_soft_budget` is `pub(crate)` — the root impl widens it, which stays a
  root-side change.) The type itself is composed from
  `tracedecay_sessions::…::LcmRetentionConfig` and
  `tracedecay_global_db::observation::retention::ObservationRetentionConfig`,
  so it could alternatively move down once those crates build.
- `TraceDecayConfig`, `cached_runtime_configuration`, `is_in_gitignore` — 3
  refs in `settings_api.rs`, all reads of resolved project configuration. A
  single read-port trait covers them.
- `SYNC_RETENTION_SETTING_KEY` — doc reference only.
