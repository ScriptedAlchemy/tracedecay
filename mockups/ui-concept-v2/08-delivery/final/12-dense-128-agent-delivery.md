# Dense 128-agent Delivery

## User job

Understand a very large Delivery, find the risky or unresolved workstream, and open one causal neighborhood without rendering a permanent lane or sidebar row for every agent.

## Product behavior

- The horizontal Delivery spine runs from human objective to delivered outcome; X is time and Y is deterministic workstream hierarchy.
- The synthetic example contains 128 unique agents. Each agent receives one primary workstream assignment for overview accounting, so the six bundle totals reconcile to 128; cross-workstream participation remains a typed link rather than double-counting the header.
- Bundles expose agent count, episode count, span, unresolved findings, named risk sources, evidence coverage, representative frontier nodes, and collapsed descendant count.
- Focus-plus-context expands the selected workstream while unrelated work compresses into density ribbons.
- The virtualized branch navigator searches and filters workstreams or task clusters, pins branches, and isolates path to root or path to outcome.
- Semantic zoom moves through Outcome, Workstream, Agent group, Agent, and Event. Exact table, tree, transcript, diff, and review fallbacks remain available.

## Truth boundary

The plate is synthetic. Generic numeric risk scores are not product authority; every implementation badge must resolve to named `test_risk`, `unsafe_patterns`, unresolved review finding, weak evidence, contradiction, or unreviewed change counts. Provider actions remain read-only.

## Production authorities

- Work owns task and workstream identity; Agents and Sessions own delegation, parentage, episodes, and persisted event provenance.
- Local Git and Code own worktree, commit, diff, symbol, and test evidence.
- Delivery owns the selected PR or umbrella outcome, review coverage, provider checks, release state, and the causal projection joining these sources.
- The deterministic layout worker owns stable bundle placement and density aggregation; it never invents attribution or causality.

## Access and scale gates

Keyboard traversal, branch search, pinned branches, high-risk or unresolved filters, focus contrast, reduced motion, 200% zoom, and an exact virtualized tree/table are required. The implementation must remain operable at 5k and 20k events without shrinking labels into unreadable microtext.
