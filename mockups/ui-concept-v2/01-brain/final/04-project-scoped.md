# Project scoped

## User job

Enter one project and see its repositories, worktrees, recent activity, and
cross-page evidence without losing the global TraceDecay navigation model.

## Product behavior

- Selection changes the URL-addressable project scope and promotes the chosen
  project into the field. The persistent scope register names the project and
  provides a clear action to return to all projects.
- Holdings, repository relations, recency, and recent admitted activity remain
  separate layers with separate legends and authorities.
- Related projects may remain as compressed context only when an exact or
  labelled inferred relation explains their presence. They never appear as
  decorative neighbors.
- Routes to Explorer, Loom, Sessions, Agents, Code, Work, and Delivery carry
  the stable project identity. Clearing scope restores the previous registry
  camera and selection when possible.

## Interaction and fallback

Users can expand repository/worktree bundles, inspect an admitted event, or
open the exact project table. Keyboard focus follows the same project and route
order. Empty, unindexed, stale, ambiguous, unavailable, and non-git states are
truthful project-scoped results, not blank success.

## Acceptance gates

Scope is conveyed through breadcrumb, text, position, and selection—not color
alone. Reduced motion removes camera travel. At 200% zoom the scope register
and exact table remain operable while the field reflows into a focus mode.
Dense project internals aggregate by repository/workstream and expand on
demand.

## Production authorities

The project registry and scoped route composition own selection. Repository,
activity, and cross-workspace links retain their own authority and evidence
grade. See [`README.md`](README.md) for named V2 composition targets.
