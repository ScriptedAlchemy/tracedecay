# Registry overview

## User job

See every TraceDecay project as one legible field, compare how much indexed
material each project holds, and understand which bodies are recent or dormant
without mistaking visual drama for health or live activity.

## Product behavior

- Each luminous body is one stable project identity. Its size is the named
  holdings measure, not a generic score; a secondary label exposes exact
  stores/files/artifacts through the production authority.
- The horizontal recency field places projects by their last authoritative
  indexing or repository observation. Unknown recency receives a separate
  unknown region instead of an invented timestamp.
- The overview is idle: no edge fires, no body blooms, and the brand glyph does
  not imply feed, connectivity, or system health.
- Search, arrow-key traversal, and the exact registry table locate bodies that
  are too small or clustered to label at the current semantic zoom.

## Interaction and evidence

Hover/focus enters [Project hover](02-project-hover.md). Selecting a project
enters [Project scoped](04-project-scoped.md). Repository structure is revealed
only through [Repository zoom](03-repository-zoom.md). Every count and recency
claim uses `EXACT`, `STALE`, `AMBIGUOUS`, or `UNAVAILABLE`; there is no decimal
confidence or hidden-reasoning inference.

## Acceptance gates

Keyboard navigation, reduced motion, the exact sortable registry table, dense
clustering, and 200% browser zoom must preserve the same selection and scope.
DOM owns text and controls; the scene owns positioned bodies and picking. The
image is concept/synthetic, not evidence that these sample projects exist.

## Production authorities

Project registry identity, enrollment, holdings, and recency feed the stable
layout. The Brain route and scoped composition targets are listed in
[`README.md`](README.md); the hybrid renderer boundary is defined in
[`IMPLEMENTATION.md`](../../IMPLEMENTATION.md).
